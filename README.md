# Closiq Sync

**Watch a video with someone else and actually stay in step.**

A Safari extension for macOS. Free, no accounts, no analytics.

[Download](../../releases/latest) · [Privacy](https://sync.closiq.app/privacy) · [Support](https://sync.closiq.app/support)

</div>

---

Start a session, send the six-character code to whoever you are watching with,
and you are lined up. Play, pause and skip work from either side, on any site
with a video.

## It nudges instead of jumping

Two computers never play at exactly the same rate, so a gap opens up over a long
film. Most tools fix that by seeking, which yanks the video for whoever gets
moved.

Closiq Sync eases the person who is *ahead* off by up to five percent, with pitch
correction, until the gap closes. You will not notice it happening. Because it
only ever slows the person in front, nobody is skipped past anything.

If one of you stalls to buffer, the other waits, then you resume together. A
pause you make yourself is never undone automatically.

## Install

1. Download the latest `.dmg` from [Releases](../../releases/latest), open it,
   and drag Closiq Sync to Applications.
2. Open it once. It will offer to take you to Safari's extension settings.
3. Turn on **Closiq Sync** under Extensions.
4. Click the toolbar button and choose **Always Allow on Every Website**.
5. Reload any tab that was already open.

That last step matters: Safari does not inject an extension into pages that were
open before you granted access.

Requires macOS 13 or later. Both people need it installed, and both need to be on
the same video. There is a test clip with a burned-in timer at
[sync.closiq.app/demo](https://sync.closiq.app/demo) if you want to prove to
yourself that it works.

## It does not know what you watch

The page address never leaves your Mac. To check you are both on the same video,
peers compare a truncated SHA-256 of the normalised URL, which cannot be reversed
into an address. What crosses the network is a room code, a playback position, a
paused flag, a rate, a buffering flag, and that hash.

No accounts, no analytics, no third parties. The relay keeps only who is
currently connected, and forgets a room twelve hours after it goes quiet.

## How the sync works

**The timebase.** Neither peer's wall clock is trusted, and they are never
compared to each other. This machine measured 111ms of offset against
Cloudflare's edge; two machines each wrong by a different amount would sit
permanently apart. Each peer instead runs an NTP-style handshake against a
Durable Object and expresses every position in that object's time.

The **lowest-RTT** sample of a batch wins, not the median: a round trip can only
be inflated by queueing, never deflated, so the fastest sample is the least
contaminated. Pinging continues for the life of the session, because calibrating
once during connection setup and trusting it forever bakes in whatever the
network happened to be doing at the worst possible moment.

**The control law.** The reference is the *slowest* peer, not a designated host,
which makes the controller slowdown-only.

| error | what happens |
| --- | --- |
| inside the deadband | nothing |
| deadband to 1.5s ahead | proportional slowdown, capped at 5% |
| more than 1.5s ahead | hold: pause and let them catch up, rather than seek backwards |
| far behind | seek, but only if a peer is wedged past a normal stall |

The deadband is `max(60ms, rtt/2)`. You cannot synchronise tighter than you can
measure, so on a slow link it relaxes instead of hunting for a target it has no
ability to see.

**Not fighting itself.** The hard part of a sync tool is that your seek fires
`seeked` on my side, which I would report as a fresh user seek, which you would
then apply, forever. Every programmatic write leaves an echo token that
suppresses the event it causes. Position cannot use a plain TTL the way `paused`
and `rate` can, because `seeked` may not arrive for seconds on a cold stream, so
it matches on proximity to the requested target instead.

## Layout

```
extension/      the Safari web extension (MV3)
  media.js      video discovery, guarded writes, echo suppression
  sync.js       clock, drift controller, follow-the-laggard state machine
  background.js owns the WebSocket, arbitrates which frame drives
app/            container-app sources copied over the generated project
worker/         Cloudflare Worker + Durable Object room server
site/           sync.closiq.app
test/sim.mjs    headless two-peer simulation, no browser needed
```

## Building

```sh
./sign-local.sh        # build, sign and install for development
node test/sim.mjs      # two-peer simulation with independent skewed clocks
./release.sh           # notarized .dmg for direct distribution
./archive.sh           # Mac App Store build
```

`build/` is generated by Apple's `safari-web-extension-packager` and regenerated
wholesale, so anything that must survive lives in `app/` or `extension/` and is
copied over it by `build.sh`.

### Things that will cost you an afternoon otherwise

- **Re-running `sign-local.sh` changes the cdhash, so Safari disables the
  extension.** Re-tick it; the host-access grant survives.
- **Changing `manifest.json` needs a version bump and a full Quit of Safari.**
  Safari caches extension code across reinstalls. Editing only JS is fine.
- **`manifest.json`'s `description` must be 112 characters or fewer.** Longer is
  rejected at App Store upload with error 90849, minutes after a full build.
- **The bundle id's capital letter is load-bearing.** The packager derives the app
  id from `--app-name` and the appex id from `--bundle-identifier`, and Xcode's
  embedded-binary prefix check is case-sensitive.
- **A blank container window proves nothing.** Screenshot APIs do not capture
  WebKit's out-of-process surface. Build Debug and read the DOM probe with
  `/usr/bin/log show --last 5m --info --predicate 'subsystem == "com.closiq.ClosiqSync"'`.
  Note `log` is a zsh builtin, so the absolute path matters.
- **Safari does not load media in a background tab.** It reports `readyState 0`
  and `networkState 3` with no error, which is indistinguishable from a corrupt
  file. Ask AVFoundation before blaming the file.
